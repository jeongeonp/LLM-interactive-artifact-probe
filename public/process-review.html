📖 Codebook

Hypothesis (user)

  • Yes: holds one option, or several but leans toward one.
  • Not a hypothesis: several options with no lean (an option set).
  • Side beliefs (e.g. salary assumptions) → optional secondary hypothesis.

Hypothesis (artifact)

  • Yes: explicitly pushes a decision: “X is best”, “A if X matters, B if Y”, or per-dimension winners.
  • No: evidence summary, ranking with no verdict (= schema), or only ruling one option out.
  • In the chat text only and not read → node engagement ignored.

Artifact relation (hypothesis row)

  • Code only when the user has a hypothesis.
  • Options: confirm / counter / no. Both = pick confirm + counter.
  • No = neutral, or played no role (went with their prior).
  • Relation and outcome are coded separately. Options and outcome are coded even with no hypothesis.

Intent

  • Information: broad (“tell me about these 4 cities”). Rare.
  • Relations: one dimension (“compare on budget”). Several chained still = relations.
  • Evidence: several criteria in one frame (“here’s my scenario, arrange them”).
  • Support: leans toward one option; checks or pushes back on the LLM’s pick.
  • Code from the query; stated expectations break ties.

Schema vs. evidence file

  • Schema: visual, spatial or relational structure (tables count), usually several dimensions.
  • Evidence file: linear text, or a ranking on one dimension.
  • Can be both.
  • User ranking options in their head across queries = schematizing → ↑ arrow.
Examples (Chicago / Minneapolis / Philadelphia session)
  • “Toss-up” artifact → hypothesis, relation confirm + counter.
  • Hospital turn → search for support; artifact = schema + evidence; hypothesis in text only → ignored.
  • “Minneapolis is #1 currently” → hypothesis; artifact confirms.
